# Skin element categories and observed nesting

Start with `just list-skin-categories`, then filter by the returned category ID:

```sh
just list-skin-elements --category=assets
just list-skin-elements --category=waveforms-position --family=skins
just list-skin-elements --uncategorized
just element button --children
just element text --parents --family=skins
just list-skin-elements --parent=button --category=text-labels
just list-skin-elements --child=text --family=video_skins
```

`--parent=button` finds elements observed directly inside a button;
`--child=text` finds elements observed directly containing text. These filters
intersect with the other filters. `--family=skin` selects both skin families,
`--family=skins` selects only skins, and `--family=video_skins` only video skins.
`--family=all` includes the other XML inventories; this nesting graph currently
covers vendor skin and video-skin XML only.

Categories are editorial navigation metadata in
[skin-element-categories.json](skin-element-categories.json), joined through
`tools/skin_categories.py`. Assets and Directives are separate. Assignments have
one primary category per family and element; family overrides allow contextual
differences. Unknown names remain Uncategorized. `just list-skin-categories`
derives unique-name totals for the selected families. With all skin families
selected, an element with different family assignments can appear in more than
one category; totals across categories are therefore not additive.

`just element <name>` gives compact category and nesting summaries alongside its
existing evidence. `--parents` and `--children` return focused relationship views
with example source locations. Add `--format=json` for all recorded source
locations. Each location's `lines` contains `[parent_line, child_line]` pairs,
using one-based source lines. The focused flags can be combined.

## Evidence and extraction boundary

[skin-xml-relations.json](../tests/skin-xml-relations.json) is generated by
`just skin-relations`. It records **observed literal direct nesting**, labeled
Tier 2, from built-in desktop/remote skins, built-in video skins, and the
Atomix-authored custom-browser example. Project-authored fixtures, personal
experiments and quarantined sources do not contribute edges. Its source manifest
retains paths, source labels, byte hashes and scan status; relationships retain
every occurrence's parent and child line.

The quote-aware nesting scanner tolerates raw script operators inside quoted
attributes. It skips comments, CDATA and processing instructions. Unbalanced
tags, unterminated constructs, unsupported declarations or multiple roots omit
the entire file's relationships and produce a diagnostic. It is a nesting
scanner, not an attribute validator or a complete XML parser.

Templates and includes are not expanded. Nesting inside a `define` is recorded
as written and is not attributed to every template use. This graph does not
establish supported children, cardinality, ordering rules or runtime behavior.
Missing relationships mean **unknown**, not unsupported. A discriminating live
skin fixture with independent readback is needed to confirm behavior; loading
without an error is insufficient. See [Evidence Standards](Evidence%20Standards.md).

The existing `just skin-classes` child-node reads remain separate binary leads:
the node passed to a helper may already be a nested node. Joining a class name
to a child lookup alone would incorrectly imply a direct-parent contract.

## Shared consumers and maintenance

- `vdj_list_skin_categories`, `vdj_list_xml_elements` and `vdj_element` expose
  the same categories, filters and relationship queries through MCP.
- `just build-reference` renders categories in the sidebar, a separate family
  filter, and linked parent/child lists. It shows the first location in each
  source file; JSON queries retain every location.
- After changing source XML, run `just inventory` and `just skin-relations`.
  After editing category assignments, rebuild the reference; the inventory
  itself needs no category regeneration.
- `just check` validates category IDs, conflicting/stale assignments, and the
  complete regenerated relationship artifact, including hashes and diagnostics.
  New unclassified inventory names remain discoverable through `--uncategorized`.

For agents, use the focused commands rather than opening the relationship JSON
or the full unfiltered element list. Start binary recovery from an ambiguous
observed relationship; keep parser reachability and live confirmation separate.
