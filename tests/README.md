# Documentation Tests

This folder contains small reproducible assets used to verify claims in the reference documentation.

Test assets are important evidence for the documentation project. They are kept outside the normal example folders so a test page, skin, mapper, or other repro fixture is not mistaken for a polished reference implementation.

| Area | Contents |
| --- | --- |
| [Pads/](Pads/) | Pad-page XML harnesses used by the VDJScript local test tracker and related source notes. |
| [Skins/](Skins/) | Skin fixtures used with local pad/controller/script tests. |
| `verb-table.json` | **Authoritative.** VirtualDJ's own verb table, extracted from a serialised record array in `__DATA,__data` (`{const char *name; uint32 id; uint32 flags;}`): 1,028 records, 955 ids, 61 alias groups, 37 editor-hidden names, and every verb's **Button Editor category** (38 categories, from a `const char *[38]` name array plus a `uint8` category-per-id array indexed by `id+1`). Membership proves a name is a verb and absence disproves it; records sharing an `id` are the same verb, `flags==1` marking the alias spelling, `flags==256` the hidden bit. Written by `tools/extract_verb_table.py`; query with `just verb-table <name>`. |
| `action-contracts.json` | **Structural contract per verb**, read from the surviving ACTION_ class RTTI: name string → `std::type_info` → vtable. Gives every one of the 955 distinct verbs its implementation class (a checked 955/955 bijection), base-class family (`toggle`/`slider`/plain), context mixins (`IActionPlugin`, `IActionSampler`), vtable length, and the override matrix — execute, generic query, specialized text query — with slot meanings calibrated from HTTP-proven verbs, not hard-coded. Also carries method-body fingerprints: `arg_demand_slots` (E_INVALIDARG materialization — 114/116 agreement with sweep needs-args, plus 301 bare-answering query verbs flagged as taking optional args) `method_strings` (per-slot string refs), and `keyword_candidates` — 259 verbs whose methods compare an argument against literals, recovering undocumented enum arguments (`get_bpm absolute|ghost`, `browser_window sidelist`, `loaded opposite`, `get_time short`). Keywords are a discovery channel: verbs silently ignore unknown words, so confirmation needs prepared state, not error codes. Agreement with the Tier-1 sweep: 652/652 on query verbs, 181/186 on action-only (the 5 outliers are the menu-verb slot-7 lead). Tier-2 structural evidence: predicts capability, not concrete type or behavior. Written by `tools/extract_action_contracts.py`; query with `just verb-contract <name>`. |
| `verb-return-types.json` | **Observed return type per query verb** (Tier 1, HTTP): all 652 query verbs sampled in three read-only contexts and classified — 334 bool, 145 int, 68 float, 4 percent, 72 text, 29 untyped. Also records **`boolean_truth`** — whether the verb is true in ternary-condition position, which is *independent of its value* — and flags `truthiness_trap` for the **171 verbs that report a true-looking value while being false** (`get_version` → `2026`, false; no slider verb is ever true). Only 106/652 query verbs are boolean-true. The authority for a verb's concrete rendered type (proves *can return*, not *always returns*); 0 capability conflicts against `action-contracts.json`. Written by `tools/sweep_return_types.py` (needs live VirtualDJ); query with `just verb-return-type <name>`. |
| `binary-verbs.json` | The **structured** verb list extracted from the app itself, unioning three sources: 1,012 mangled `ACTION_<name>` implementation classes, 812 `languages.zip` catalog entries, and the parser's 967-entry alphabetically sorted name table (which is where **aliases** live). 1,076 names, covering 998 of the 1,007 the HTTP sweep proved real; flags 63 `alias_candidate` names (in the table with no implementation class of their own). Membership proves a name is real; absence is NOT a disproof. Written by `tools/extract_binary_verbs.py`; query with `just binary-verb <name>`. |
| `verb-existence-sweep.json` | HTTP existence probe for every verb-store name plus candidates-doc names: status (`exists`/`unresolved`), kind (`query`/`action-only`/`needs-args`/`context-gated`/`false-here`), the HRESULT, and a live sample value for query verbs. Written by `tools/sweep_verb_existence.py`; query with `just verb-probe <name>`. Proves existence and kind only, never behavior. |
| `verb-arg-forms.json` | **What a verb's tail accepts** (Tier 1, HTTP). 483 verbs × 4,430 forms — bare, each candidate token, and ordered pairs — probed inside each named fixture, every reading measured against **two nonsense controls**, because an unknown argument is silently ignored so "it answered" proves nothing. A form counts as `recognized` only where it separates from garbage in at least one state; failing to separate is not evidence of absence, and a token recognized in any run stays recognized with `not_reproduced_in` noting where it did not repeat. Carries `pair_shape` per two-token form (`first-token-wins`, `singles-agree`, `last-token-wins`, `beyond-singles`) — only the last two are evidence of real two-token grammar. Guards: `disputed_verbs` (verdict flipped between runs — `get_cpu`, `is_using`), `undiscerning_verbs` (matched most of an arbitrary vocabulary, so drifting rather than speaking it — `get_time`, `param_cast`, `record_vu`, `pioneer_cue`). Written by `tools/probe_arg_forms.py`; query with `just verb-arg-forms <name>`. |
| `action-catalog.json` | **The vendor's own prose, offline.** `Resources/languages.zip` → `English.xml` → `<Actions>` is the same text the official verbs appendix publishes at virtualdj.com — verified verbatim for `auto_bpm_transition` — so 816 descriptions are readable without the network. 97 verbs document parameters, 18 promise more than one argument. **The only source that says what a parameter MEANS**; probes can only say a token is not nonsense. Its `--cross-check` diffs documented parameters against the probe and corpus artifacts three ways. Written by `tools/extract_action_catalog.py`; query with `just action-catalog --get <name>`. |
| `vdjscript-corpus.json` | **Every VDJScript snippet Atomix wrote**, deduped with provenance: 1,131 from shipped Built-In pad/skin/samplerbank/videoskin XML (usage — what the parser demonstrably accepts), 269 quoted inside catalog descriptions (documentation — what a form means), 41 transcribed from the official wiki, and **83 compiled into the app binary** — the statements behind its own menus and toolbars, read from the `__cstring` pool (`sideview 'clone'`, `font_size 'big'`, `show_splitpanel 'info'`, `sideview 'automix' 'blink'`), 80 of them in no other source. Only `Built-In` trees are read; `examples/Pads/Quarantine` and this repo's own skins are excluded so our fixtures cannot masquerade as vendor evidence. Binary strings pass a statement filter (verb first, script tokens after, one marker no prose has) because `set`, `select` and `color` are verbs and the pool also holds ffmpeg's option help. Written by `tools/extract_script_corpus.py`; query with `just script-corpus --verb <name>`. |
| `attested-tails.json` | **Argument tails recovered from those snippets** — 214 tokens on 95 verbs, 147 unknown to both the binary's `keyword_candidates` and the catalog; 22 tokens on 15 verbs are attested only by the binary-embedded statements (`show_splitpanel effects|info`, `scratch_dna_option continue`, `browser_options le`). **Also argument SHAPES with return evidence** (`shapes`, added 2026-09-03): tails are vocabulary, so a verb whose arguments are values had nothing — `fadeout 10000ms 3000ms \`loop\`` yielded no candidate at all, and 114 verbs with vendor examples were invisible. Every statement now also contributes its tail classified as DUR/PCT/NUM/REL/STR/VAR/BOOL/KW, plus NAME for a bare keyword that is also a verb name (`loop_roll video`, `hold toggle` — a keyword for most verbs). An **expression argument reduces to the type its inner verb returns**, since that is what the callee receives, from the Tier-1 return-type sweep: a backticked one is written `` `BOOL` `` / `` `NUM` `` / `` `STR` `` (`` `?` `` when the inner verb is unmeasured), and a bare one under a `param_*` comparator, whose bare words are expressions, `EXP:NUM` (`param_bigger pitch pitch_slider`). The surface form is kept in the shape because it changes behaviour — transport verbs reject a computed argument where the literal works — so `fadeout DUR DUR \`BOOL\`` and a hypothetical `fadeout DUR DUR BOOL` stay distinct: 410 shapes on 262 verbs, 167 of them verbs with no keyword tail at all. The `deck` wrapper is not a verb but grammar — a selector and the rest of the statement as an expression, `deck SEL EXP` — so it is unwrapped (the inner verb gets its shape, marked `wrapped_by`) and the 15 selectors the vendor used (`1`–`4`, `left`, `right`, `master`, `all`, `leftvideo`, `rightvideo`, `[SWAPDECK]` …) are counted under `wrappers`. Each shape carries `returns`: the attribute the vendor wrote it into (`color` ⇒ color, `value` ⇒ number, `visibility` ⇒ bool or a fade level; counted only for the chain's last statement, and a constraint rather than a pin), the catalog's "returns …" prose, the Tier-1 bare-form sweep type, and the structural query flags. `just verb-arg-forms` now points at the shapes instead of claiming a shaped verb "needs no args". Attestation needs no probe: a tail Atomix shipped is a form the parser accepts, which covers exactly the gap where no fixture can discriminate. Filters drop the three false-parameter classes this repo has already retracted once — symbol fragments (`TION_get_text`), prose sentences opening with a verb-like word, and statement suffixes (`dump while_pressed`). Written by `tools/extract_attested_tails.py`; query with `just attested-tails --verb <name>`. |
| `binary-vocabularies.json` | **Argument vocabularies as GROUPS**, recovered from the binary as structures rather than per verb. Every other argument source is per verb, but an enumeration is usually shared — one helper matches stem names for `stem_color`, `stems_split` and `effect_stems`; one table holds every colour name — and per-verb analysis cannot see it: 67 of the corpus's attested tails are in the binary but outside their verb's own code. Three signals, recorded separately and weakest first: a string-pool **run** (neighbours, never promoted alone), a **code region** that references two or more members (a switch walking the enumeration; every other word it references is a candidate), and a **pointer table** in `__DATA_CONST` (the serialised structure itself, entries in order). 21 groups, 265 members, 190 unknown to every per-verb source. Pointer tables found: 38-entry colour names (`beige`, `marine`, `violet`, `transparent`, `reset` …), the 5 stems (`vocal hihat bass instru kick`), sideview pages, the 19 settings pages (`settings 'audio'` and its siblings), the 17 pad-page names, the 17 song fields. **Tier 2, discovery only**: a member is a lead for `probe_arg_forms.py`, and verbs silently ignore unknown words, so confirmation needs a fixture where the forms would differ. Written by `tools/extract_binary_vocabularies.py`; query with `just binary-vocab --get <group>` / `--verb <name>` / `--tails`. |
| `corpus-parse-results.json` | **The corpus run through `/query`**, and the first check here that can *falsify* a grammar claim. 1,167 of 1,516 parse and none contradicts [VDJScript Grammar](../docs/VDJScript%20Grammar.md); the failures map the channel's boundary instead — 33 surface-gated action verbs, 15 pipeline forms (`& param_*` wants a value HTTP cannot supply), 14 execute-position semantics (`loop 50%` multiplies rather than sets; the binary's `sampler_bank +1`, `pad_page +1` and `deck master sampler_bank -1` are relative steps, which query position rejects with `E_INVALIDARG`), 29 `E_FAIL` (silence, not denial). All five binary statements written with `&&` (`browser_window sideview && sideview 'sidelist'`) parse, so the parser accepts `&&` as a conjunction on this channel. Query-only by design: the corpus contains `load`, `unload` and `browsed_song color`. Written by `tools/check_corpus_parses.py`. |
| `verb-execute-forms.json` | **Tails measured in EXECUTE position**, where the query path is blind — `deck all` broadcasts on execute and collapses to deck 1 on query. Each form is run from **two baselines** (`off` and `on`), which is what separates *set* (`yes`,`yes`) from *flip* (`yes`,`no`) from *no-op* (`no`,`yes`); from one baseline `beatlock on` and `beatlock <junk>` are indistinguishable. Writes to a live instance, so: allowlist only, each verb round-trip tested first, every value restored and verified, abort on a failed restore. Written by `tools/probe_execute_forms.py`. |
| `action-vtables-9246.json` | **Every `ACTION_` vtable slot resolved to a named method**, from bundle `18.0.9246` — the last unstripped build (321,571 symbols; `18.0.9482` onward keep ~1,210). Names the 12-slot layout the current build can only infer: 2 `onExecute`, 3 `onQuery`, 4 `onQueryBool`, 5 `onQueryText`, 6 `onTooltip`, 7 `onUp`, 8/9 `onSaveState`/`onLoadState`. `overridden_slots` agrees 950/952 with the current build, so names transfer — but a single verb's contract still comes from the current-build RTTI. Written by `tools/extract_action_vtables.py`. |
| `vdjremote-opener.bin` | Raw opening handshake captured from a real VirtualDJ Remote device (app build 8515), the reference input for `tools/vdjremote_dial.py --decode` and the prefix reused by `tools/vdjremote_subscribe.py`. Backs [docs/Remote Protocol.md](../docs/Remote%20Protocol.md). |
| `vdjremote-actions.log` | Decoded device→desktop action frames captured while a real device's controls were touched, including the timed press sequence that maps play/cue/crossfader/volume to control ids. |
| [Stems/](Stems/) | Stem-file generators for `docs/Stem File Format.md` claims. `make-diagnostic-stems.zsh` builds probe files where the master is white noise and each stem a distinct sine tone (100/200/400/800/1600 Hz = kick/bass/vocal/instruments/hihat), so pad→stream routing and master↔stems switching are verifiable by ear; includes a stamped vs unstamped writing-application sidecar A/B. |
